# Wallet Interface Structural Reorganisation (#507)

## Context

PR #561 merged the network ontology redesign, which deleted `ChainProvider`, `NullChainProvider`, `WhatsOnChainProvider` from the wallet and removed the `chain_provider:` constructor param from WalletClient. The `chain/` subdirectory items are done. Three phases remain.

The wallet's `lib/bsv/wallet_interface/` directory has 23 files at root level with `WalletClient` at 1,825 lines and 96 methods spanning 6+ responsibilities beyond BRC-100. UTXO state transition logic is duplicated between WalletClient and InlineQueue. BRC-29 key derivation is duplicated between ChangeGenerator and ReplenishmentWorker. ProtoWallet inheritance is composition in disguise. A circular dependency exists: WalletClient -> LocalPool -> ReplenishmentWorker -> WalletClient.

Each phase is a separate PR with its own branch.

---

## Phase 1: Directory Reorganisation (low risk)

Pure file moves. No logic changes. No namespace changes.

### Move 10 files into 3 subdirectories

**`storage/`** (5 files):
- `storage_adapter.rb` -> `storage/storage_adapter.rb`
- `memory_store.rb` -> `storage/memory_store.rb`
- `file_store.rb` -> `storage/file_store.rb`
- `proof_store.rb` -> `storage/proof_store.rb`
- `local_proof_store.rb` -> `storage/local_proof_store.rb`

**`broadcast/`** (2 files):
- `broadcast_queue.rb` -> `broadcast/broadcast_queue.rb`
- `inline_queue.rb` -> `broadcast/inline_queue.rb`

**`pool/`** (3 files):
- `utxo_pool.rb` -> `pool/utxo_pool.rb`
- `local_pool.rb` -> `pool/local_pool.rb`
- `replenishment_worker.rb` -> `pool/replenishment_worker.rb`

### Files staying at root

`wallet_client.rb`, `proto_wallet.rb`, `interface.rb`, `validators.rb`, `certificate_signature.rb`, `key_deriver.rb`, `version.rb`, `coin_selector.rb`, `change_generator.rb`, `fee_estimator.rb`, `fee_model.rb`, `wire.rb`, `substrates.rb`

### Approach: flat namespace, no module files

Classes stay in `BSV::Wallet::` namespace (not `BSV::Wallet::Storage::` etc.). There are 99 references across 34 files including bsv-wallet-postgres (`include StorageAdapter`, `include BSV::Wallet::BroadcastQueue`, `BSV::Wallet::MemoryStore.new`). Nesting would break all of these.

Unlike `Wire`/`Substrates` (which use nested namespaces because they're implementation details), storage/broadcast/pool classes are the gem's public API surface.

**Only file modified:** `wallet_interface.rb` — update autoload paths from e.g. `'bsv/wallet_interface/memory_store'` to `'bsv/wallet_interface/storage/memory_store'`.

No module files needed. No spec changes. No downstream gem changes.

### Order of operations

1. Create directories: `storage/`, `broadcast/`, `pool/`
2. `git mv` each file (10 moves)
3. Update autoload paths in `wallet_interface.rb`
4. Run `bundle exec rake spec:wallet` — all 34 specs pass
5. `cd gem/bsv-sdk && gem build bsv-sdk.gemspec` — verify gem builds (gemspec uses `Dir.glob`)

### Acceptance criteria

- [ ] All 34 wallet spec files pass unchanged
- [ ] bsv-wallet-postgres specs pass (if available)
- [ ] No files remain at root for the 10 moved files
- [ ] `BSV::Wallet::MemoryStore`, `BSV::Wallet::InlineQueue`, `BSV::Wallet::LocalPool` etc. all resolve

## Phase 2: WalletClient Responsibility Extraction (medium risk)

Target: reduce `wallet_client.rb` from 1,825 lines to ~500 lines.

### Extraction 1: UTXOStateManager (highest value — eliminates duplication)

**New file:** `wallet_interface/utxo_state_manager.rb`

Unifies duplicated code:
- `InlineQueue#promote` (lines 172-176) and `WalletClient#promote_no_send` inline (lines 1438-1440) — functionally identical
- `InlineQueue#rollback` (lines 187-197) and `WalletClient#release_pending_utxos` (lines 1316-1324) — byte-for-byte identical

```ruby
class UTXOStateManager
  def initialize(storage:)
  def promote(input_outpoints, change_outpoints, txid, status: 'completed')
  def rollback(input_outpoints, change_outpoints, txid, fund_ref, action_status: 'failed')
  def release_pending_utxos(outpoints, ref)
end
```

**Consumers:**
- `InlineQueue` — constructor takes `state_manager:`, delegates `promote`/`rollback`
- `WalletClient` — instantiates `UTXOStateManager`, delegates state transitions

### Extraction 2: Expand Validators module

**Modify:** `wallet_interface/validators.rb`

Move 8 private validation methods from WalletClient (lines 1084-1147, 1715-1731):
- `validate_create_action!`, `validate_action_inputs!`, `validate_action_outputs!`
- `validate_list_actions!`, `validate_list_outputs!`, `validate_internalize_action!`
- `validate_acquire_certificate!`
- `validate_broadcast_configuration!` — takes `broadcast_enabled:` boolean param

All are pure functions on args hashes. WalletClient calls `Validators.validate_create_action!(args)`.

### Extraction 3: TransactionBuilder

**New file:** `wallet_interface/transaction_builder.rb`

Extract 12 private methods from WalletClient (lines 1151-1285, 939-1021):
- `parse_input_beef`, `build_transaction`, `build_inputs`, `wire_source`, `wire_source_from_storage`, `wire_source_tx_ancestors`, `build_outputs`, `shuffle_outputs`, `needs_signing?`
- `build_auto_funded_transaction`, `add_auto_funded_input`, `add_output_from_spec`

Constructor: `TransactionBuilder.new(storage:, proof_store:, key_deriver:)`

### Extraction 4: InternalizationHandler

**New file:** `wallet_interface/internalization_handler.rb`

Extract 6 private methods from WalletClient (lines 1613-1711):
- `store_proofs_from_beef`, `extract_subject_transaction`, `find_by_subject_txid`
- `process_internalize_outputs`, `internalize_payment`, `internalize_basket`

Constructor: `InternalizationHandler.new(storage:, proof_store:, key_deriver:)`

### Extraction 5: CertificateManager

**New file:** `wallet_interface/certificate_manager.rb`

Extract 6 private methods from WalletClient (lines 1734-1822):
- `acquire_via_direct`, `acquire_via_issuance`, `auth_fetch_client`
- `execute_http`, `find_stored_certificate`, `cert_without_keyring`

Constructor: `CertificateManager.new(storage:, key_deriver:, wallet:, http_client: nil)`
(Needs `wallet:` for `AuthFetch.new(wallet: self)` — Phase 3 cleans this up)

### What stays in WalletClient

- All 28 BRC-100 public methods (now thin delegation)
- Storage helpers (`store_action`, `store_tracked_outputs`, `store_change_outputs`, `build_action_query`, `build_output_query`, `strip_*_fields`) — closely tied to action data format
- `auto_fund_and_create` orchestration (moved to AutoFunder in Phase 3)
- `finalize_action`, `create_signable`
- Pending state maps (`@pending`, `@pending_by_txid`)

### Order of operations

1. Create UTXOStateManager, update InlineQueue + WalletClient
2. Expand Validators, update WalletClient
3. Create TransactionBuilder, update WalletClient
4. Create InternalizationHandler, update WalletClient
5. Create CertificateManager, update WalletClient

## Phase 3: Composition Refactor (higher risk)

### Change 1: Make ChangeGenerator#build_output public

Add public wrapper `build_single_output(satoshis:)` to ChangeGenerator. Delete `ReplenishmentWorker#build_pool_output` (the duplicate).

### Change 2: Break circular pool/wallet dependency

`ReplenishmentWorker` currently takes `wallet_client:` and reaches into `wallet_client.key_deriver`. After Change 1, it only needs `create_action` and `change_generator`.

Refactor to accept callables:
```ruby
ReplenishmentWorker.new(
  pool: pool,
  create_action: method(:create_action),  # callable
  change_generator: auto_change_generator  # ChangeGenerator instance
)
```

Remove `wallet_client:` from both `ReplenishmentWorker` and `LocalPool` (LocalPool only held it to pass through).

### Change 3: ProtoWallet to composition

`WalletClient` no longer inherits `ProtoWallet`. Instead:
- Includes `Interface` directly
- Holds `@crypto` collaborator (either `ProtoWallet.new(key)` or the substrate)
- Declares own `attr_reader :key_deriver`
- All 9 crypto methods delegate to `@crypto`

### Change 4: Extract AutoFunder

**New file:** `wallet_interface/auto_funder.rb`

Extract 10 auto-fund methods (~350 lines) from WalletClient:
- `auto_fund_and_create`, `auto_fund_select`, `converge_change`, `load_pool_opts`
- `auto_fee_estimator`, `auto_coin_selector`, `auto_change_generator`
- `store_change_outputs`, `change_output_entry`, `spendable_pool_eligible?`

Constructor: `AutoFunder.new(storage:, key_deriver:, broadcast_queue:, utxo_state_manager:, ...)`

### Order of operations

1. Make ChangeGenerator#build_output public, update ReplenishmentWorker
2. Break circular dependency (refactor ReplenishmentWorker + LocalPool constructors)
3. Replace ProtoWallet inheritance with composition
4. Extract AutoFunder
5. Update autoloads

### Test impact

- `replenishment_worker_spec.rb` — update setup: replace `wallet_client:` with `create_action:` lambda + `change_generator:`
- `local_pool_spec.rb`, `pool_health_spec.rb` — remove `wallet_client:` from constructor
- `wallet_client_spec.rb` — inheritance-related assertions change (ancestors check)
- `proto_wallet_spec.rb` — unchanged (ProtoWallet itself is unmodified)

### Acceptance criteria

- [ ] All specs pass
- [ ] `WalletClient.ancestors` does not include `ProtoWallet`
- [ ] `ReplenishmentWorker` source has no reference to `wallet_client` or `WalletClient`
- [ ] `LocalPool` source has no reference to `wallet_client` or `WalletClient`
- [ ] No circular dependency in the object graph
- [ ] `wallet_client.rb` under 300 lines
